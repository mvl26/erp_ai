# ADR-001: Một module Frappe `ERP AI agent` và bốn tầng mã phụ thuộc một chiều

- Trạng thái: proposed
- Ngày: 2026-11-11

## Bối cảnh
- H-1 (spec `:158`): module thật của app là `ERP AI agent`, thư mục `erp_ai/erp_ai_agent/` (`erp_ai/modules.txt:1`, `erp_ai/hooks.py:2`). Guide lại đặt DocType ở `erp_ai/erp_ai/doctype/` (guide `:634`) và gọi method theo đường `erp_ai.erp_ai.doctype...` (guide `:931`). Repo chưa có DocType nào (assessment `:16`), nên chốt lúc này chưa tốn migrate. Đổi sau khi đã có DocType thì phải migrate trường `module` của từng DocType.
- Nhiều task độc lập sẽ cùng thêm mã: trigger, runner, tool, cổng gọi API, scheduler, cài đặt, eval. Có ba ràng buộc chỉ kiểm được bằng chiều import: NFR-1 (không gọi model trong luồng lưu), AC-3 (eval và agent dùng chung một prompt phân loại), AC-8 (tool không tự gọi model hay tự chạy agent).
- Trong bench còn một app khác dùng chung env Python và SDK là `workflowcore` (research `:35`). FEAT-001 không được đụng tới app khác (intake).

## Quyết định
1. Giữ module `ERP AI agent`. Mọi DocType và Report của app nằm trong `erp_ai/erp_ai_agent/doctype/` và `erp_ai/erp_ai_agent/report/`. Không tạo module thứ hai, không tạo thư mục `erp_ai/erp_ai/`.
2. Mã ngoài DocType chia thành bốn tầng, mỗi tầng một chỗ:

| Tầng | Vị trí | Vai trò |
|---|---|---|
| Cửa vào | handler `doc_events` và scheduler (ở gốc gói `erp_ai/`, tên file do designer chọn, mặc định theo guide `:619-621`), mã cài đặt, method whitelist trong controller DocType, `erp_ai/eval/` | Nhận sự kiện, lịch, lệnh của người; gọi xuống tầng dưới |
| Lõi agent | `erp_ai/agent/` (runner, chính sách kích hoạt/mức quyền, thẩm quyền, prompt + bộ đọc kết quả phân loại, registry tool, `erp_ai/agent/tools/`) | Quyết định chạy gì, với bộ tool nào |
| Cổng model | `erp_ai/gateway/` | Mọi giao tiếp với Claude API (ADR-002) |
| Dữ liệu | DocType của app, DocType của Frappe/Helpdesk, đọc/ghi qua ORM | Lưu trữ |

3. Chiều phụ thuộc: Cửa vào → Lõi agent → Cổng model → (SDK, ORM). Cửa vào chỉ được gọi thẳng Cổng model trong ba trường hợp: chạy eval, nút "Kiểm tra khóa", job dò lại khóa mỗi giờ.

## Ràng buộc
- `erp_ai/modules.txt` có đúng một dòng `ERP AI agent`. Mọi file JSON DocType/Report của app có `"module": "ERP AI agent"`. Không tồn tại thư mục `erp_ai/erp_ai/`.
- `erp_ai/gateway/**` không import `erp_ai.agent`, `erp_ai.eval`, handler, scheduler hay mã cài đặt.
- `erp_ai/agent/**` không import `erp_ai.eval`, handler, scheduler hay mã cài đặt.
- `erp_ai/agent/tools/**` không import `erp_ai.gateway` và không import runner. Tool không gọi model và không đưa job agent vào hàng đợi.
- File handler `doc_events` không import `erp_ai.gateway` và không import runner; job được đưa vào hàng đợi bằng chuỗi đường dẫn hàm (ADR-003).
- `erp_ai/eval/**` không chứa bản sao nội dung prompt phân loại. Eval import prompt và bộ đọc JSON từ `erp_ai/agent/` (AC-3).
- `erp_ai/**` chỉ import mã của `frappe`, `helpdesk` và thư viện khai trong `pyproject.toml`; không import `workflowcore` hay app nào khác. `hooks.py` khai `required_apps` có `helpdesk`.

## Phương án đã xét
- Đổi module thành `ERP AI` cho khớp guide `:634`: phải sửa `modules.txt` và `app_title`. Lợi ích duy nhất là chép nguyên đường dẫn method của guide, mà mã guide vốn chỉ là mẫu (assessment `:18`) → không chọn.
- Đặt runner/tool trong thư mục module (`erp_ai/erp_ai_agent/agent/`): trộn mã Python thường vào thư mục Frappe dành cho DocType/Report. Đường `erp_ai.agent.runner.run_for_ticket` mà guide `:1025` dùng sẽ phải đổi → không chọn.
- Không chia tầng (mọi file ngang hàng): ít thư mục hơn, nhưng reviewer không còn grep được NFR-1 và AC-8 → không chọn.

## Hệ quả
- Tốt: H-1 chốt trước DocType đầu tiên. Ba ràng buộc NFR-1, AC-3, AC-8 thành luật import mà reviewer kiểm được bằng grep.
- Xấu: phải viết lại đường dẫn trong mã mẫu của guide: `erp_ai.erp_ai.doctype.*` → `erp_ai.erp_ai_agent.doctype.*`, `erp_ai.agent.client` → `erp_ai.gateway`.
- Phải làm thêm: designer đặt tên file trong từng tầng. Reviewer grep import theo các dòng Ràng buộc ở mỗi task.
